# Offline macOS OCR + Ollama translation (single-machine prototype)

Run `python3 server/local.py` on macOS. Apple Vision and Swift compiler (`swiftc`, Xcode Command Line Tools) are required for OCR; the server compiles `server/vision_ocr.swift` on first OCR into the system scratch directory. A running Ollama service with downloaded `gemma3:4b` is required for translation. The fixed Ollama endpoint is `127.0.0.1:11434`; `GAM264_OLLAMA_MODEL` may select a different *already installed local* model before starting the server. No cloud endpoints, user PDF files, or input PNGs are written by these APIs; PNG bytes travel to Apple Vision over stdin. The server is loopback-only, not a multi-user or LAN deployment.

Both endpoints require `POST`, `Content-Type: application/json`, a `Host` of `127.0.0.1` or `localhost`, and a matching `Origin: http://<Host>`. JSON bodies have a 9 MB limit.

- `/api/ai/ocr`: `{"image":"<base64-encoded PNG>"}` → `{"blocks":[{"text":"...","x":0,"y":0,"w":100,"h":20,"confidence":0.9}],"warnings":[]}`. Blocks are recognized lines; coordinates are PNG pixel units from **top-left**. Maximum base64 payload 8 MiB (about 6 MiB decoded) / 32 megapixels; renderer/frontend sends each PDF page as PNG. OCR does not process PDFs directly and does not modify their bytes.
- `/api/ai/translate`: `{"items":[{"id":"1","text":"Remove sharp edges."}],"glossary":{"EJECTOR PIN":"頂針"}}` → `{"items":[{"id":"1","text":"Remove sharp edges.","translation":"去除銳邊。"}],"model":"gemma3:4b"}` (example shape only; actual `text` echoes the **original text**, not translated text). Up to 20 entries of 2,000 characters, glossary up to 100 terms. Each item may have `skipped` or `warning`. Pure Han text and standalone dimensions/tolerances/identifiers/units are skipped. Mixed text's glossary terms, dimensions, tolerances, identifiers, and units are masked; if a model edits protected markers, the server retries unprotected spans separately and reconstructs protected values itself. Any remaining invalid token/number result returns an item-level `error` without `translation`, rather than being applied. Model unavailable, busy, or timeout yields 503; no online or synthetic translation fallback.

The frontend keeps the original drawing text and offers translations as reviewable overlays only. OCR can misread tiny text and symbols, and model output is not a verified engineering translation. A single rejected model item now returns an item-level `error` without a `translation`; accepted items become black/white editor-only drafts as batches finish. The editor lists every rejected source with its page and reason; a stop button completes the current batch and releases the editor so early drafts can be inspected. A 503 (model offline/busy) or malformed batch stops processing but retains drafts from earlier completed batches. Rerunning skips existing draft sources and retries unresolved sources. **Partial processing, a stopped run, or rejected items must never be represented as a completed translation.** Drafts need human retention (✓ 保留); only retained notes enter preview/export. Retention/export are not blocked by overlap or overflow: note geometry stays fixed, the appearance clips to its bounds, and full text stays in edit data and PDF annotation Contents. The adjacent 保留本頁所有翻譯 / 刪除本頁所有翻譯 controls affect only current-page AI notes in one undoable transaction, not manual notes or other pages; edits and undo/redo invalidate file completion. The glossary button/panel have been removed; previously saved browser-local glossary data remain compatible and are not deleted. Repeated identical source strings are translated once per run and fanned out to their positions. A dense 10-page drawing may yield over a thousand candidate text blocks; runtime and full-page translation quality have not been validated on the customer sample. Test locally: `python3 -m unittest tests.test_local_ai -v` (includes real Apple Vision and Ollama calls using synthetic input).
